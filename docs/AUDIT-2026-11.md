# MINIMICAL DROP — Production code audit
Date: 2026-11-07 (Asia/Kolkata)

## Scope and method

Static source inventory across the repository's application pages, API handlers,
server helpers, database schema/migrations, build scripts, CSS, configuration,
and documentation. Manually reviewed critical paths for admin authentication,
Google OAuth, Drive access and ownership, file/folder actions, upload sessions,
resumption, delivery status, and project creation. Inspected Vercel production
runtime/build errors and Supabase database health/security/performance advisories.

**Constraints:** No destructive production action, no secret extraction, no
production branch merge, and no modifications to existing client data.
A live browser device matrix and authenticated Google OAuth/upload roundtrip
were not run from the review environment.

## Database posture and migration

- Private business tables use RLS with no public policies, matching the application's
  server-only access model. **Do not** add anonymous access policies to remove these
  informational notices.
- Apply `supabase/migrations/007_hardening_indexes.sql` after review.
- Search path fixes target `reserve_upload` and `touch_upload_activity`.
- Indexes target `audit_events(project_id,created_at)`, `folders(parent_id)`,
  `projects(drive_account_id)`, and `uploads(folder_id)`.
- Other tables flagged in broader project advisories can belong to other apps;
  do not change them as part of MINIMICAL DROP.

## Remaining risks and recommendations

1. The original build scripts still **rewrite source files**. Longer-term: commit
   their effects directly into source and remove the string replacement pipeline,
   instead of relying on build-time regexes.
2. `package.json` uses unpinned `latest` dependencies with no committed lockfile.
   Capture the currently verified installed versions and commit a lockfile before
   the next major dependency update. Avoid blind upgrades while production works.
3. The in-memory application rate limiter is **per process**, not global across
   Vercel instances. Configure Vercel Firewall/WAF rules for admin login and
   public token endpoints as described in `docs/SETUP.md`.
4. Live preview screenshots and functional OAuth/large-file upload checks require
   a controlled browser session and test Google account; not proven by compilation.
5. RLS security and query plan advisories should be rechecked **after** applying
   the prepared migration. Do not modify unrelated Supabase project tables.
6. Keep a backup/restore strategy for Supabase metadata and Google Drive data,
   and ensure client upload links can be revoked in emergencies.

## Manual acceptance checklist (before production merge)

- [ ] At 360, 390, 768, 1024, and 1440px: no horizontal page overflow; project modal
      buttons and file controls are reachable; focus visible and keyboard Escape works.
- [ ] Sign in/out; admin chrome survives temporary Supabase unavailability.
- [ ] Connect Google Drive using `https://drop.minimical.online/admin`; confirm
      existing Drive account is updated and client projects remain associated.
- [ ] Create a test project and verify no duplicate after retry; archive it after checks.
- [ ] Upload a zero-byte file, small image, PDF, video, and large resumable file;
      interrupt and resume once; validate quota handling and the cleanup job.
- [ ] Confirm JPG/PNG/PDF/video previews work; SVG/HTML download but cannot execute inline.
- [ ] Rename/delete a managed file and nested folder; test that a moved file
      outside its project is not deleted by an old link.
- [ ] Client delivery approval/change-request/comment and optional email notifications.
- [ ] Apply and verify migration 007 under change control, then rerun Supabase advisors.
